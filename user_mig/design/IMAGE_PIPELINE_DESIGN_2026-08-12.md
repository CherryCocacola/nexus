# 이미지 파이프라인 설계안 — 코딩 API 입구 + 재질의 가능한 이미지 맥락

작성 2026-08-12 · **v2 (Fable5 검토 반영)** · 상태: 구현 착수

> **v1 → v2 변경 요약**
> v1 은 코딩 API 의 기존 계약 두 가지를 놓쳤고, 그 탓에 설계 C 가 주 소비자(VSCode
> 플러그인)에서 성립하지 않았다. 검토에서 차단 2건이 나왔고 아래에 반영했다.
> ① 도구 풀 통째 교체와의 충돌 → **혼합 풀 계약 변경**을 명시(3.B)
> ② 무상태 재전송에 의한 디스크 증폭 → **해시 멱등 저장**을 필수로 승격(3.A)
> ③ 보존 기간 문제를 **표면별로 분리**(3.C)
> ④ C 를 "코드 강제"가 아닌 **넛지**로 정정하고 승격 조건 명시(3.D)
> ⑤ 입력 검증·상한 항목 반영(3.F)

---

## 0. 한 줄 요약

코딩 API 가 이미지를 못 받는다. 그리고 웹·API 공통으로, 한 번 분석한 이미지를
**나중에 다시 물을 수 없다.** 두 구멍을 함께 막는다.

---

## 1. 확인된 사실 (전부 실측·코드 확인)

| # | 사실 | 근거 |
|---|---|---|
| F1 | 코딩 API 는 `content` 배열을 **422** 로 거부 | `web/app.py:1140` `content: str \| None`. 실서버 3케이스 |
| F2 | 막히는 이유는 이미지가 아니라 **배열 형식** | 텍스트만 든 배열도 422 |
| F3 | 비전 능력 자체는 있다 | Gemma3-27B, 터널 18004 |
| F4 | `AnalyzeImage(image_path, question)` — 질문을 받는다 | `analyze_image_tool.py:165-186` |
| F5 | 원본을 **줄이지 않고** base64 로 VLM 에 보낸다 | 같은 파일 `call()` |
| F6 | `image_path` 는 업로드 샌드박스 하위만 허용 | `_resolve_uploaded_image` → 밖이면 **DENY** |
| F7 | 업로드는 영속화돼 있다 | `uploads_dir: /app/data/uploads` |
| F8 | **보존 24시간** | `retention_hours: 24` |
| F9 | 웹은 이미 대화에 "서버 경로" 를 남긴다 | `index.html` `readFileContents()` |
| F10 | 상한 불일치 — 업로드 20MB vs 비전 10MB | `max_size_bytes` vs `DEFAULT_MAX_IMAGE_MB` |
| **F11** | **`tools` 가 오면 도구 풀을 통째로 교체한다** | `web/app.py:997` `session_tools = client_tools if client_tools else parts["web_tools"]` |
| **F12** | **코딩 API 는 무상태 — 요청마다 새 UUID** | `web/app.py:2703`. 클라이언트가 히스토리 전량 재전송 |
| **F13** | Pillow 는 설치돼 있으나 **선언은 없다** | 로컬 12.1.1 / 컨테이너 12.3.0, `requirements`·`pyproject` 에 없음 |

**F11·F12 가 v1 이 놓친 것이다.** F11 때문에 플러그인 요청에는 `AnalyzeImage` 가
존재하지 않고, F12 때문에 같은 이미지가 턴마다 새 파일이 된다.

---

## 2. 문제 정의

- **P1** 코딩 API 에 이미지 입구가 없다.
- **P2** 재질의가 안 된다 — 첫 요약만 남아 모델이 기억으로 때운다.
- **P3** 세부가 안 읽힌다 — VLM 내부 전처리 축소로 작은 글씨가 뭉개진다.

---

## 3. 설계

### A. 코딩 API 가 `content` 배열을 받는다 (+ 해시 멱등 저장)

`OpenAIChatMessage.content` 를 `str | list[dict] | None` 으로 넓히고 정규화한다.

```
텍스트 파트    → 이어 붙여 본문
image_url 파트 → data URL 만 허용 → 저장 → 본문에 핸들 덧붙임
```

**A-1. 원격 URL 불허.** 에어갭 위반 + SSRF. `data:` 만.

**A-2. ★해시 멱등 저장 — 선택이 아니라 필수.**
F12 때문에 같은 이미지가 매 턴 재전송된다. 파일명을 내용 **SHA-256** 으로 정하고
이미 있으면 쓰지 않는다. 없으면 30턴 대화가 같은 20MB 를 30벌 쌓는다(600MB).

```
uploads_dir / f"img-{sha256[:32]}.{ext}"   # 있으면 skip
```

**A-3. 파일명은 서버가 만든다.** 클라이언트 파일명을 믿지 않는다(경로 주입).

### B. ★혼합 도구 풀 — 계약 변경 (F11 대응)

**변경 전**: `tools` 가 오면 풀을 통째로 교체 → 서버 도구 0개.
**변경 후**: 교체하되 **`AnalyzeImage` 만 서버 실행 도구로 잔류**시킨다.

이유: C(재질의)의 유일한 성립 조건이다. 부를 도구가 없으면 핸들을 실어 줘도 소용없다.

**B-1. 이것은 보안 태세의 부분 되돌림이다 — 제약을 명시한다.**
서버 도구를 뺀 이유는 실측 사고였다(테넌트 키 하나로 `tenants.yaml` 전량 열람).
그래서 예외를 좁게 못 박는다.

| 제약 | 강제 방법 |
|---|---|
| 잔류 가능 도구 = **`AnalyzeImage` 하나** | 화이트리스트 상수 + 테스트로 목록 고정 |
| read-only 이고 업로드 샌드박스 밖은 DENY | F6 이 이미 강제. 테스트로 재확인 |
| 그 외 서버 도구가 새어 들어오면 실패 | 혼합 풀에 `is_client_executed=False` 가 추가되면 테스트 실패 |
| 프롬프트↔풀 불일치 금지 | `_client_tools_instruction` 이 잔류 도구를 함께 안내. 과거 `알 수 없는 도구: 'Agent'` 와 같은 버그 유형 |

**B-2. 대안(기각).** *eager 분석* — 정규화 시점에 서버가 VLM 을 바로 불러 요약을
본문에 넣는 방식. 계약 변경이 없어 안전하지만 **재질의가 불가능**해 P2 를 못 푼다.
→ 위 제약이 거부되면 이쪽으로 후퇴한다(기능 축소를 명시적으로 감수).

### C. 이미지 핸들 유지 — 표면별로 다르다 (F8 대응)

대화에 안정적인 핸들을 남긴다.

```
[이미지 #1] 파일명: chart.png · 서버 경로: /app/data/uploads/img-<hash>.png
```

**C-1. 보존 24시간 문제는 표면마다 다르다.** v1 은 이를 뭉뚱그렸다.

| 표면 | 만료 시 | 판단 |
|---|---|---|
| **코딩 API** | 클라이언트가 data URL 을 계속 재전송 → **같은 해시로 재생성** | 문제 아님 |
| **웹** | 경로만 남아 있어 재생성 불가 | **여기가 급소** |

→ 웹은 **명시적 만료 알림**(기본). `AnalyzeImage` 가 이미 "파일을 찾을 수 없습니다"
를 내므로, 실제 작업은 그 오류에 **"보존 24시간 만료" 맥락을 붙이는 것뿐**이다.
추가로 해시 멱등 저장이 디스크 부담을 줄이므로 `retention_hours` 를 **72** 로 올린다.

### D. 재호출 유도 — 이것은 "코드 강제"가 아니다 (정정)

v1 은 C 를 "코드로 강제"라고 썼다. **틀렸다.** 핸들을 실어 주는 것은 **넛지**이며,
모델이 옛 요약으로 때우는 것을 막지 못한다.

**D-1. 1차 구현**: 세션에 이미지가 있으면 **항상** 핸들을 싣는다(참조 감지 없음).
감지 규칙은 반드시 새고, 핸들 한 줄은 토큰이 거의 안 든다.

**D-2. 승격 조건**: e2e "재질의 시 `AnalyzeImage` 재호출" 이 **실패하면**, 서버가
사용자 질문 그대로 `AnalyzeImage` 를 대신 실행해 결과를 그 턴에 주입하는 방식으로
승격한다. 판정은 **도구 호출 로그**로 한다 — 답변 텍스트로 판정하지 않는다.

### E. `region` 인자 추가 (P3)

```
AnalyzeImage(image_path, question, region=[x, y, w, h])   # 0~1 비율
```

F5 대로 원본을 그대로 보내므로, 자른 조각은 같은 픽셀 예산 안에서 해상도가 올라간다.

**E-1. 비율 좌표.** 모델은 원본 픽셀 크기를 모른다. "왼쪽 위" = `[0, 0, 0.5, 0.5]`.
**E-2. Pillow 명시 선언이 선행**(F13). 지금은 전이 의존성이라 상위 패키지가 바뀌면
조용히 사라지고, 에어갭 오프라인 번들에서 누락된다.

### F. 입력 검증·상한 (검토 지적 반영)

| 항목 | 규칙 |
|---|---|
| **디코딩 전 차단** | base64 **문자열 길이**로 먼저 자른다. 디코딩 후 검사면 이미 메모리를 썼다 |
| **매직 바이트** | MIME 화이트리스트로 부족. 시그니처 확인 + Pillow `verify()`(압축 폭탄) |
| **상한 통일** | F10 → 비전 상한을 업로드와 같은 **20MB** 로. base64 팽창(20MB→약 27MB JSON)은 위 선차단이 흡수 |
| **`is_tool_continuation`** | 도구 결과로 이어 도는 턴은 `append_user_message=False` 경로다. 핸들 주입이 **새 user 메시지를 만들면 안 된다** |

## 4. 하지 않는 것

| 안 함 | 이유 |
|---|---|
| 대화 전체를 비전 모델로 전환 | 모델 교체 = 샘플링 3모드 재실측 + 컨텍스트 불변식 재계산 + API 방언 |
| 원격 URL 이미지 | 에어갭 위반 · SSRF |
| 첫 분석을 구조화 전문으로 | A~E 가 되면 효과 중복. 토큰만 먹는다 |
| 이미지 이해의 완전한 영속 | 텍스트 모델이 주력인 한 불가능. 재질의로 대체 |
| 혼합 풀에 도구 추가 | `AnalyzeImage` 하나로 고정. 늘리려면 별도 판단 |

---

## 5. 남는 한계 (정직하게)

- 재질의는 **원본이 남아 있는 동안만** 유효하다(웹 한정 제약, C-1).
- 비전 모델이 매번 새로 보므로 같은 질문에 **답이 미세하게 달라질 수 있다**.
  temperature 0.2 라 세부 표현 수준의 변동이며, "안정적으로 틀린" 첫 요약 고정보다
  낫다고 판단했다.
- D-1 은 넛지다. 모델이 옛 요약으로 때우는 것을 **막지는 못한다**(D-2 승격 조건).

## 6. 구현 단계 · 검증

각 단계마다 커밋하고, 실패하면 그 단계에서 멈춘다.

| 단계 | 내용 | 검증 |
|---|---|---|
| **S1** | `content` 정규화 + 해시 멱등 저장 + F 검증 | 단위(문자열/텍스트배열/이미지배열/혼합/빈 배열/깨진 data URL/경계 크기) · 실서버 200 · **멱등 e2e: 같은 히스토리 2회 → 파일 수 불변** |
| **S2** | 혼합 풀 + 프롬프트 정합 | 화이트리스트 고정 테스트 · 프롬프트↔풀 일치 테스트 · 실제 `tool_calls` 확인 |
| **S3** | 핸들 상시 삽입(웹·API) + 만료 문구 + `retention_hours` 72 | 재질의 시 **도구 재호출 로그** · `is_tool_continuation` 무회귀 |
| **S4** | `region` + Pillow 선언 + 상한 통일 | 크롭 전후 작은 글씨 판독 비교 · 좌표 경계값 |

**무회귀 필수**: 문자열 `content` 200 유지 · 웹 업로드 경로 불변 · `tools` 없는
소비자 응답 형태 불변.
