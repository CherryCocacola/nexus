# 표면 회귀 E2E — 배포 전후에 돌리는 스위트

배포된 서버를 **실제로 두들겨** 웹·OpenAI API·VSCode(구조화 출력)·테넌트 격리가
도는지 확인한다. mock 을 쓰지 않는다.

## 왜 있는가

2026-08-20, 단위 테스트 2,600여 개가 전부 통과하는 동안 실서버는 코딩 요청마다
**HTTP 404** 를 뱉고 있었다. 코더 라우팅은 08-05 에 만들어져 **15일간 한 번도 동작한
적이 없었다.** 단위 테스트는 값을 검증하지 **경로를 통과시키지 않기** 때문이다.

같은 날 테넌트 격리 결함도 이 방식으로 찾았다 — 다른 테넌트 키로 남의 대화 전문이
읽혔다. 엔드포인트 단위 테스트만으로는 드러나지 않는 종류다.

## 실행

```bash
# 기본 대상 = 112 배포 서버
pytest tests/e2e/test_surface_http.py tests/e2e/test_surface_documents.py \
       tests/e2e/test_tenant_isolation_e2e.py -q

# 다른 서버를 겨냥할 때(로컬 기동 등)
NEXUS_E2E_BASE=http://127.0.0.1:8600 pytest tests/e2e -m e2e -q

# 테넌트 키를 바꿔서
NEXUS_E2E_KEY=<primary> NEXUS_E2E_KEY2=<second> pytest tests/e2e -m e2e -q
```

서버에 닿지 않으면 **자동 스킵**된다. 그러니 전체 `pytest` 를 돌려도 실패하지 않는다.

## 배포 절차에 넣는 법

1. 배포 **전** — 현재 서버 상태를 한 번 찍어 둔다(무엇이 이미 깨져 있었는지 구분).
2. `docker cp` + 재시작.
3. 배포 **후** — 같은 스위트를 다시 돌린다. 전부 통과해야 배포 완료로 본다.
4. 실패하면 스냅샷 이미지로 롤백한다(`nexus-web:pre*-<날짜>`).

`/health` 200 만으로 정상 판정하지 않는다 — 과거에 그렇게 판정했다가 부트스트랩이
죽은 채로 전 요청이 401 이던 사고가 있었다.

## 무엇을 보는가

| 파일 | 범위 |
|---|---|
| `test_surface_http.py` | 생존·모델목록·도구풀·인증·비스트림·한국어·SSE·멀티턴·function calling·구조화 출력·query_class·웹 채팅·오류 사유 |
| `test_surface_documents.py` | 업로드→도구 파싱→문서 생성→다운로드. 프런트가 실제로 쓰는 두 첨부 형식으로 확인 |
| `test_tenant_isolation_e2e.py` | 격리 **차단**과 소유자 **정상동작**을 쌍으로 |

## 설계 원칙 둘

**① 차단만 보지 않는다.** 격리를 넣고 "막혔다"만 확인했더니, 정작 소유 테넌트가
자기 세션을 못 읽는 회귀가 배포된 채로 있었다. 차단 테스트와 정상동작 테스트는
반드시 쌍으로 간다.

**② 설정을 복사하지 않는다.** 회귀 스위트를 만들 때 설정 사본을 떠 두었다가,
그 사본이 낡아 **가짜 실패**가 났다. 테스트는 리포·환경변수에서 직접 읽는다.

## 주의

- 이 스위트는 배포 서버에 **실제 대화와 문서를 만든다**(세션·exports 가 쌓인다).
  운영 데이터를 건드리지는 않지만, 테스트 세션이 목록에 보이는 것은 정상이다.
- 모델 생성이 포함돼 1분 30초쯤 걸린다. GPU 가 바쁘면 더 걸린다.
